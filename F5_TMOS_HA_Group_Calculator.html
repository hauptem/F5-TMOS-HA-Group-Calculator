      User Guide

      Use

      1. Set the platform trunk limit (8, 16 or 32 links).
      2. Add trunks and set members, links up, minimum threshold, sufficient threshold (0 = all members) and weight (10 to 100).
      3. Set the active bonus (default 10). The ACTIVE device holds the traffic group; Fail to Standby moves it to the peer.
      4. Every change is one monitor interval. The traffic group moves when the peer score is strictly higher and stays there until a later change moves it back.
      5. Auto failback returns the group to the preferred device after it has been eligible for the configured delay (default 60 s). A link that recovers for less than the delay does not trigger failback.
      6. The failover matrix shows the outcome of each possible link loss on the active device. Sync copies configuration from Member 1 to Member 2; Copy link captures the scenario in the URL.

      Scoring

      • Contribution = INT(weight × MIN(up, sufficient) / sufficient); sufficient defaults to the member count.
      • A trunk below its minimum threshold contributes 0 and zeroes the device score. A device with score 0 is ineligible and receives no bonus.
      • Device score = sum of contributions plus the active bonus on the device holding the traffic group.
      • Failover requires a strictly higher peer score. Equal scores keep the current device.
      • Trunks only. Pools, VIPRION clusters, VLAN failsafe and gateway failsafe are not modelled.
